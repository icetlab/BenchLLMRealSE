The original code's primary performance bottleneck is the creation of a new string via `s.toLowerCase()`. This operation allocates memory proportional to the string's length (O(N) space complexity) and requires a full pass over the string to create the lowercase version.

My improvement eliminates this intermediate string allocation. The updated code iterates through the input string just once, comparing adjacent characters case-insensitively using `Character.toLowerCase()`. This approach reduces the auxiliary space complexity from O(N) to O(1) and avoids the overhead of object creation and a second iteration, resulting in better memory efficiency and faster execution, especially for long strings.
