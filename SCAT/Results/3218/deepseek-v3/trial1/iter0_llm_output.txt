We need to improve the performance of the given code. The main inefficiency is that for each node, we collect all values in its subtree, sort them, and then compute the answer. This results in O(n² log n) time complexity in the worst case. 

The key optimization is to only keep the 5 most relevant values (2 smallest and 3 largest) at each node, since the maximum product of 3 numbers can only come from either the 3 largest or the 2 smallest and 1 largest. This reduces the sorting overhead significantly.
