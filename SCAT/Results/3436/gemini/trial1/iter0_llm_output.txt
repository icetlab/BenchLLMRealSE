The original solution uses a Segment Tree and binary search for each starting position, leading to an `O(N * log^2 N)` time complexity. This is inefficient and prone to off-by-one errors in the binary search bounds, which exist in the provided code.

The improved solution leverages a key property of the bitwise OR operation: for any fixed endpoint, the number of distinct OR values of subarrays ending at that point is very small (at most ~30, related to the number of bits in an integer). This is because the OR value is non-decreasing as the subarray extends to the left, and each new distinct value must set at least one new bit.

By iterating through the array and maintaining a set of these distinct OR values, we can achieve a much faster `O(N * log(MAX_VAL))` solution. This approach is also significantly simpler, more memory-efficient, and avoids the bugs present in the original complex implementation.
