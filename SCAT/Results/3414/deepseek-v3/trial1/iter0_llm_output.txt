## Improvement Intent

The current solution uses recursion with memoization but has several performance issues:
1. **Excessive recursion depth** - The `up()` method doubles the stair number each time, causing exponential growth in the state space
2. **Inefficient caching** - Using `Move` records as map keys creates many objects and hashing overhead
3. **Unnecessary state exploration** - The algorithm explores many states that can never reach the target `k`

The key insight is that this problem has a mathematical pattern: the number of ways to reach stair `k` follows a specific sequence related to powers of 2. We can replace the recursive approach with a direct mathematical computation.
