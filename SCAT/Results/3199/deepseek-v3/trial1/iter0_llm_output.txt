## Improvement Intent

The original code uses three nested loops iterating up to `n` (which can be large, e.g., 50), resulting in O(n³) time complexity. We can optimize by reducing the loops: since `i + j + k = n`, once we choose `i` and `j`, `k` is determined as `n - i - j`. We only need to check if `k` is within the limit and non-negative. This reduces complexity to O(n²) and eliminates the innermost loop entirely.
