Looking at the code, I notice the main performance issue is in the binary search section where the calculation of `l1`, `r1`, `l2`, `r2` ranges and the counting of ones within those ranges is inefficient. The current approach recalculates prefix sums for each binary search iteration, but the logic for determining which positions to include is overly complex and can be simplified.

The key improvement is to directly compute the minimum moves by considering the positions of ones relative to index `i`, rather than using the complex binary search with range calculations.
