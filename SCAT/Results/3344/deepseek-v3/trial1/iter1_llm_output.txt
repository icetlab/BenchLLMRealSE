The previous optimization failed because the `findTwoExtremes` method does not correctly handle duplicate values. When the minimum or maximum value appears multiple times, removing one occurrence should still leave another occurrence available. The current logic incorrectly treats duplicates as if they were a single value.

A simpler and correct approach is to keep the original `TreeSet` logic but optimize it by precomputing the top two smallest/largest values **with their indices**, so we can correctly determine the min/max after removing each point.
