**Explanation of the fix:**
The key insight is that the condition should be: two numbers are a valid pair if they are equal OR if one is directly in the other's single-swap variant set. This exactly matches the original semantics:
- `nums[i] == nums[j]` handles the equal case
- `variants[i].contains(nums[j])` checks if `nums[j]` can be obtained from `nums[i]` by one swap
- `variants[j].contains(nums[i])` checks the reverse direction

This avoids the false positive where two numbers share a common variant but require multiple swaps to transform into each other. The precomputation of variants makes the pair checking O(1) per pair instead of O(L²) where L is the number length, improving performance while maintaining correctness.
