The original solution has a time complexity of roughly O(N^2 * L^3), where N is the number of elements in the input array and L is the maximum number of digits in a number. This is due to the nested loops iterating through all pairs of numbers, and for each pair, performing an expensive check that involves generating all possible single-digit swaps.

My approach significantly improves performance by pre-processing the input array and categorizing the numbers, which avoids the expensive O(N^2) pair-wise check. The strategy is as follows:

1.  **Frequency Counting**: First, I count the occurrences of each number using a `HashMap`. This reduces the problem from operating on N numbers to M unique numbers, which is beneficial if there are many duplicates.

2.  **Group by Anagrams**: I group all unique numbers by their "canonical form," which is the string of their sorted digits. All numbers that are anagrams of each other will fall into the same group. This step has a complexity of O(M * L log L).

3.  **Count Pairs within Groups**:
    *   **Identical Pairs**: For each number with count `c > 1`, we can form `c * (c - 1) / 2` pairs. This is calculated efficiently.
    *   **Anagram Pairs**: Within each anagram group, I check pairs of distinct numbers. Since they are anagrams of the same length, checking if one can be formed from the other by a single swap is a fast O(L) operation: we just count the number of differing character positions, which must be exactly 2.

4.  **Count Non-Anagram Pairs**: The trickiest pairs are non-anagrams, like `(10, 1)`. This relationship occurs when a single swap in the larger number (e.g., "10") creates a leading zero, resulting in a smaller number (e.g., `Integer.parseInt("01")` is `1`). These pairs are handled by iterating through each unique number, and if it contains a non-leading zero, I simulate a swap with the first digit to generate a potential "partner" number. If this partner exists in our frequency map, we've found a valid pair. This process is unidirectional (from the larger number to the smaller), ensuring each pair is counted exactly once.

This optimized approach breaks down the problem into smaller, more manageable subproblems, replacing the O(N^2) brute-force check with more efficient data structures and targeted calculations, leading to a substantial performance gain.
