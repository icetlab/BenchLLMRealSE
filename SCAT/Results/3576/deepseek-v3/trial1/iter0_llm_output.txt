Looking at this code, I can see it's solving a problem where we need to find subtree sizes after reparenting nodes based on character matching. The main performance issues are:

1. Using `HashSet` for adjacency lists when we need ordered iteration and frequent removals
2. Creating two separate adjacency structures when we could work with one
3. Using `Integer[]` for tracking closest nodes when a simple `int[]` would suffice
4. The recursive DFS could be optimized with better data structures

Here's my improvement plan:
- Replace `HashSet` with `ArrayList` for adjacency lists (better for iteration and memory)
- Use primitive `int[]` instead of `Integer[]` for tracking closest nodes
- Optimize the DFS to avoid unnecessary object allocations
- Use iterative approaches where possible to reduce recursion overhead
