We need to optimize the recursive backtracking solution. The current approach explores all possible combinations, which can be exponential. We can improve it using memoization (dynamic programming) with bitmask for visited rows, since the number of rows is small.

The key insight: we process values in descending order, and for each value, we try to assign it to an unvisited row. The state can be defined by (current value index, visited rows bitmask). We can memoize results to avoid recomputation.

**Explanation of improvement:**  
The original solution uses recursive backtracking with a `Set<Integer>` for visited rows, which leads to repeated exploration of the same subproblems. We replace this with a bitmask representation for visited rows and add memoization based on the current value and the visited mask. This dramatically reduces the number of recursive calls by caching results for identical states, turning an exponential-time algorithm into a polynomial one (bounded by the number of distinct values × 2^rows).
