The original code uses a recursive backtracking approach to find the maximum score. The state of the recursion is defined by an upper bound for the next number to select and a set of rows that have already been used. For larger grids, this can lead to re-computing the solution for the same state multiple times, resulting in poor performance.

My main improvement is to introduce memoization to cache the results of the recursive function `maxHelper`. This avoids redundant computations for the same subproblems, which are defined by the pair `(num, vis)`. The state `(num, vis)` represents the maximum score achievable with values less than `num`, given that rows in the `vis` set are already occupied. By storing and retrieving results from a hash map (`memo`), we can significantly reduce the number of recursive calls, turning an exponential complexity algorithm into a pseudo-polynomial one (in terms of the number of reachable states).

Additionally, I've made a minor improvement to the `createTreeMap` method by using `computeIfAbsent` for a more concise and potentially slightly more efficient way to populate the map.
