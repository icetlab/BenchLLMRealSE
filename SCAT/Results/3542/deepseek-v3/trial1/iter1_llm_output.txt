I need to optimize the Java solution by reducing redundant computations. The current approach sorts each row and then for each of the top 3 cells in each row, it scans all rows to find the best two other cells. This is O(m * 3 * m * 3) = O(9m²) which is acceptable, but we can improve constant factors by precomputing the top 3 cells for each row once, then for each pair of rows, computing the best two cells from those rows with distinct columns. This avoids repeated sorting and reduces object creation overhead.
