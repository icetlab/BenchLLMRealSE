The performance of the provided code is primarily limited by the `check` method, which determines how many numbers up to a given value `v` are divisible by at least one of the `coins`. The original implementation calculates this using the principle of inclusion-exclusion by iterating through all `2^n - 1` non-empty subsets of coins. For each subset, it computes the least common multiple (LCM) from scratch, leading to an overall time complexity of `O(n * 2^n)` for the `check` method.

My improvement focuses on optimizing this `check` method. I will replace the nested loops with an iterative, dynamic programming-style approach. This new approach builds the LCMs for all subsets incrementally. It starts with an empty set and, for each coin, generates new subsets by combining the coin with all previously generated subsets. This avoids recalculating LCMs and reduces the time complexity of the `check` method to `O(2^n)`.

Additionally, the new implementation includes two important micro-optimizations:
1.  It uses a safer calculation for LCM (`(a/gcd(a,b))*b`) to prevent potential intermediate `long` overflows.
2.  It prunes the computation by skipping the generation of new subset LCMs if they are guaranteed to exceed the target value `v`, which can provide a significant speedup when `v` is relatively small during the binary search.
