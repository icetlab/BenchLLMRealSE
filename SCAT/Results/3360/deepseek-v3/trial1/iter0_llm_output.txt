## Improvement Intent

The original code has several performance issues:
1. **Redundant calculations**: The sums for left and right parts are recalculated in every iteration of the while loop and if conditions, leading to O(n²) complexity.
2. **Inefficient sliding window**: The logic for maintaining the window and computing deletions is overly complex with unnecessary nested loops.
3. **Unnecessary sorting overhead**: While sorting is needed, the subsequent processing can be optimized.

The key insight is that we can use prefix sums to compute deletions in O(1) time per window position, reducing overall complexity from O(n²) to O(n log n) (due to sorting).
