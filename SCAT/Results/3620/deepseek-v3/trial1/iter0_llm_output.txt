Looking at this code, I can see several performance issues:

1. **Unnecessary data structures**: Using `List<int[]>` and `Set<Integer>` adds overhead. The problem can be solved with simple sorting and greedy selection.
2. **Redundant checks**: The `selected.contains(val)` check is unnecessary since we're already ensuring `val >= cnt` (which tracks the next available value).
3. **Inefficient memory usage**: Storing ranges as arrays and using a HashSet when we only need a count.

The optimal approach is to sort the original array, then greedily assign the smallest possible value in each range while ensuring distinctness. This reduces time complexity from O(n log n) with extra overhead to O(n log n) with minimal overhead, and space from O(n) to O(1) extra space.
