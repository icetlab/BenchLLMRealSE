## Improvement Intent

The main performance bottleneck is using `HashMap<String, Integer>` for memoization, which creates many string objects and has high overhead. I'll replace it with an `int[]` array for faster lookups. The state space is bounded by `n * m * (1<<19)`, but we can optimize by using a 2D array keyed by `(i, j)` and storing the best `and` value separately, or using a more compact representation. Since `and` values are limited (19 bits), I'll use a 3D array with dimensions `[n+1][m+1][1<<19]` but only allocate for needed sizes. However, to keep memory reasonable, I'll use a 2D array of HashMaps or a single HashMap with a custom key. The best approach is to use a 2D array of `int[]` where each entry maps `and` values to results, but that's complex. Instead, I'll use a single `HashMap<Long, Integer>` with a packed key `(i << 40) | (j << 20) | and` to avoid string concatenation overhead.
