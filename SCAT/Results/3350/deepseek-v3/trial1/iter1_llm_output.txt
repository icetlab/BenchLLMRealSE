Looking at the test failure, the issue is that when values are equal, the original code used `v + 0.5` for binary search, which ensures that equal values are placed after existing equal values (since `v + 0.5 > v`). When I changed to using integers directly with `Collections.binarySearch(os1, v)`, equal values get inserted at the position of the first occurrence, changing the order.

The fix is to use `v + 1` instead of `v` in the binary search, which preserves the original behavior of placing equal values after existing ones, while still using integers for efficiency.
