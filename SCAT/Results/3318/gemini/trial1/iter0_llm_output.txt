The primary performance bottleneck in the original code is the use of `String` concatenation to create keys for the memoization map. String creation, hashing, and comparison are significantly slower than using a primitive type like `long`.

My improvement strategy is to replace the `String`-based memoization key with a `long`. Since the constraints on the array length `n` (up to 2000) and element values (up to 1000) are moderate, the state `(i, j, score)` can be encoded into a single `long` value using bitwise operations. This avoids the overhead of `String` objects, leading to a substantial performance gain.

Additionally, I've made minor improvements for correctness and readability:
1.  Added a guard clause to handle arrays with fewer than two elements.
2.  Refactored the logic inside the methods to be slightly clearer while preserving the original algorithm.
