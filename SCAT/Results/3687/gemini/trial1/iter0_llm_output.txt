The original solution's performance bottleneck is within the `DFS` method. When a node with a duplicate value is found on the current path, the code enters a `while` loop to shorten the path and recalculate the `pathSum` by subtracting edge weights one by one. In a skewed tree (like a line graph), this could lead to a time complexity approaching O(N^2), where N is the number of nodes.

My improvement replaces this inefficient recalculation with a prefix sum technique. During the DFS traversal, I maintain a list of prefix sums of edge weights from the root to the current node's depth. When a path needs to be redefined due to a duplicate value, the new path's sum can be calculated in constant time by subtracting the prefix sum at the new start of the path from the current node's prefix sum. This optimization reduces the overall time complexity to O(N), as each node is processed in constant time on average during the traversal. I also added a check for an empty graph (`n=0`) for robustness.
